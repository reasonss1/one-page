# 框图表达：让结构和关系直接看得见

框图不是把每段话都套个边框。先确定读者要判断什么，再用位置、分区标题和连线把答案、依据、限制和相互关系摆出来。正式汇报、方案比较、会议总览或复杂材料先从[场景成稿索引](playbook.md)选一个样式，而不是从空白画框。一句就能答清的反馈不硬套版面。

## 先画版面，再放内容

1. **先定第一眼。** 把主题和回答放在页首，给当前结论、阻塞或请求最高的视觉层级。会改变结论的条件放在同一框或紧挨着，不埋到页尾。
2. **分区，每框有题。** 一个框回答一个读者问题。标题写成扫一眼就能懂的内容，如「场地未确认」而不只是「其他」。把相同层级的框对齐，留出空白；别用几段密集文字填满一个框。
3. **用摆放方式表达关系。** 并列是可对比，先后是有次序，箭头是有方向的关系。只在有事实依据时连接；条件和分支写在连接处或目标框里。颜色和粗细只分主次，必须用文字说明状态，不能靠红绿猜。
4. **把需要采取的行动放到读者找得到的地方。** 只写实际需要的动作和已知条件。负责人、时间、审批或结果没有确认就标未知或省略，不为了填满图而虚构。

## 按关系选形状

| 要看清的关系 | 推荐布局 | 别这样画 |
|---|---|---|
| 一个结论由什么支撑 | 上方结论框＋下方有标题的依据／限制框 | 把阻塞丢到页脚，或让全部框同样醒目 |
| 几个选项怎么选 | 同层并列；方案用相同字段、相同口径对齐 | 为首选项多摆有利维度；用箭头串无先后关系的选项 |
| 下一步要等什么 | 状态或条件框 → 动作框；分支标明「满足／不满足」或实际条件 | 把待做节点画成已完成；图上画了箭头却没说明关系 |
| 时间、趋势或量级有何差异 | 有数据才用时间线或小图表；标题点出要看的差异，标清时间、单位和口径 | 用无数据的装饰图，或靠颜色传递唯一含义 |

## 同一套方法，两种版面

- **自用整理页（Excel1）：** 顶部放待答问题，下方用小格平铺候选或事实，一格一条；用位置、编号或文字说明哪些归类、入选、待核实。不要在发散时把最早写下的候选做成主结论。
- **给人看的汇报页（Logic3）：** 顶部放结论和关键限制，下方按读者的关键问题分框；每框先放直接回答，再放可核对的依据。涉及对比或依赖时再并排或连线，不从头到尾画成一条流程。

## 交付与检查

- **交付介质服从阅读任务。** 对话先用 Markdown，纯文本用[分隔线样式](../assets/layouts/plain-text.txt)。需要独立传阅、打印或明确要图时，可用能复制文字的 HTML 或 SVG，按需另给图片或 PDF；参考[可编辑框图示例](../assets/visual-one-page-example.html)与[效果图](../assets/visual-one-page-example.png)。不要假定对话窗口会渲染任意 HTML 或 Mermaid。
- **扫读检查。** 不读正文，能否只看页首、框标题、连线就说出「结论是什么、卡在哪、什么条件下能推进」？再核对框里的证据与原材料，确保未验证项不会被误读成已完成。
- **显示检查。** 窄屏用单列保持阅读顺序；不靠空格硬对齐。要求实际 A4/A3 单页时检查打印或导出的页数、裁切与字号；内容超界就调版或分层，不藏关键条件、不压成小字。没有预览就说明未验证。
